## Описание задач

### 1. Скелет репозитория
Структура: `src/notify/domain`, `src/notify/api`, `src/notify/channels`, `tests/`, `docs/`. Настроен менеджер зависимостей, линтер, `.gitignore`, `.env.example`.
**Готово, когда:** проект ставится по README, пустой тест запускается командой `pytest`.

### 2. Доменное ядро
Класс `Notification` с состояниями и таблицей разрешённых переходов; недопустимый переход приводит к `InvalidTransition`. Ядро не импортирует FastAPI и SQLAlchemy.
**Готово, когда:** тесты проверяют все разрешённые и все запрещённые переходы (параметризованно).

### 3. Registry, Dispatcher, Channel
Контракт `Channel.send(recipient, message) -> ToolResult`; `Registry.register/get`, ошибка «неизвестный канал»; `Dispatcher` вызывает канал через `Registry` и переводит состояние по `ToolResult`; `LogChannel`.
**Готово, когда:** новый тестовый канал подключается без правки `Dispatcher`; тесты на неизвестный канал и неверные параметры.

### 4. S1: создание и отправка
`POST /notifications`, сохранение в `accepted`, воркер берёт уведомление и вызывает `Dispatcher`.
**Готово, когда:** выполнены критерии приёмки S1; тест полного пути с fake-получателем.

### 5. S2: идемпотентность
Ключ хранится с уведомлением (уникальное ограничение), повтор возвращает то же уведомление, другое тело даёт `409`.
**Готово, когда:** выполнены критерии S2, есть тест на одновременные запросы.

### 6. S3: отмена
`POST /notifications/{id}/cancel`, условный переход `accepted → cancelled`.
**Готово, когда:** выполнены критерии S3, включая `409` для всех остальных состояний.

### 7. S4: просмотр
`GET /notifications/{id}` и `GET /notifications?status=`, в ответе история попыток.
**Готово, когда:** выполнены критерии S4.

### 8. S5: валидация и ошибки
Единый формат ошибок во всём API, коды `unknown_channel`, `invalid_params`, `missing_idempotency_key`, `bad_request`.
**Готово, когда:** выполнены критерии S5, каждая ошибка имеет тест.

### 9. S6: адаптер и fake
HTTP-адаптер с timeout 5 с, 2 повторами, классификацией причин (`timeout`, `rejected_by_receiver`, `bad_response`), fake-получатель с режимами ответов.
**Готово, когда:** выполнены критерии S6, интеграционные тесты идут против fake.

### 10. Хранилище и миграции
Таблицы `notifications`, `delivery_attempts`; миграции Alembic; репозиторий-слой между API и БД.
**Готово, когда:** чистая БД поднимается миграциями, откат работает.

### 11. CI
Workflow запускает линтер и `pytest` на каждый PR.
**Готово, когда:** на PR виден зелёный/красный статус; настроен запрет вливания при красном CI.

### 12. Диагностика
Middleware `X-Correlation-ID`, JSON-логи, `/health` (с проверкой БД), настройки из переменных окружения.
**Готово, когда:** в логах одного запроса везде один `correlation_id`; `/health` отвечает `503` при недоступной БД.

### 13. Docker Compose и PostgreSQL
Сервисы `app`, `postgres`, `fake-webhook`; миграции применяются при старте.
**Готово, когда:** `docker compose up` из чистого клона поднимает рабочий сервис.
